t3-feedback test page

The Widget below talks to the two echo Receivers started by npm run test-page. They keep each Feedback instead of opening a Thread, and the "Open thread" link shows what was received.

Three Machines are configured: nowhere, whose Receiver never answers, then echo and echo2. On a Staging page these probes are what trigger the browser's one-time local-network permission prompt (Chrome 142+, Firefox 151+); the loopback Receivers here do not prompt.

  • The "Send feedback" button appears bottom right once every probe has answered or given up: about 4 s here, because nowhere only gives up at the timeout. The chooser lists echo and echo2 only.
  • and reload: the chooser defaults to echo, the first online Machine.
  • Send a message and check the "Open thread" link: project, machine, message, pageUrl, viewport, and userAgent are filled in.
  • Choose echo2 and send: the "Open thread" link shows echo2 as the machine, and the terminal logs the Feedback on echo2. Reload: the chooser defaults to echo2.
  • In the network panel, the POST to /feedback has no OPTIONS preflight before it.
  • Paste a screenshot into the message: a thumbnail appears. Pasting text still inserts the text.
  • Paste or pick a second image: it replaces the first. On a phone, "Attach image" opens the photo picker.
  • The "Open thread" link shows the image's type, size, and dimensions. A small PNG arrives unchanged; an image over about 1.5 MB, or one that is not PNG or JPEG, arrives as a JPEG no wider or taller than 1920 px.
  • Ctrl/Cmd+Enter sends, Escape closes, and Send is disabled while a send is in flight.
  • Stop npm run test-page and send again: the error names the chosen Machine, with the Tailscale hint.
  • This page loads a hostile stylesheet. and the Widget looks the same either way.
  • Go to another page with Turbo Drive: the Widget stays, open and with its text, and is not duplicated.
  • Open a page whose only Machine never answers: no button appears.
  • Restart with npm run test-page -- --jsdelivr to load the released Widget from jsDelivr instead of widget/; the terminal prints which URL the pages use. Everything above behaves the same, except for changes made since that release.
